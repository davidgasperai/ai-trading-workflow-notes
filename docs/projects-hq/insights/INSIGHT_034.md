Title

Define Failure Before It Happens

Core Idea

A resilient system should define unacceptable behavior before encountering it.

Failure criteria, intervention thresholds, and shutdown conditions should be designed in advance—not invented while the system is already under stress.

Why It Matters

When an AI agent, trading strategy, or automated workflow begins behaving unexpectedly, decisions made in the moment are vulnerable to bias.

It becomes tempting to wait longer, change the rules, add another filter, or explain away evidence that contradicts the original hypothesis.

Predefined failure conditions remove much of that ambiguity.

The system knows when autonomy must decrease, when human intervention is required, and when an experiment should stop.

Impact on Nekonečný Mír

* Define failure conditions before deploying an agent or strategy.
* Establish risk thresholds before capital is exposed.
* Specify when an agent must stop and escalate to a human.
* Never change failure criteria simply to rescue a disappointing experiment.
* Separate temporary anomalies from genuine invalidation.
* Document kill, pause, and review conditions before production use.
* Treat stopping correctly as a successful system behavior—not as failure.

Projects HQ Principle

The best time to define when to stop is before you want to continue.
