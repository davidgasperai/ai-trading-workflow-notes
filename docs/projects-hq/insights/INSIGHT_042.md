Title

New Capability Requires New Validation

Core Idea

A system that becomes more capable is not automatically the same system, only better.

New capabilities can invalidate assumptions that were safe under the previous version.

Therefore every material increase in agent capability should trigger a review of validation, permissions, monitoring and containment.

Why It Matters

AI systems evolve quickly.

A model upgrade may improve reasoning, coding, tool use or autonomy without changing the surrounding application architecture.

This creates a dangerous illusion:

the interface looks unchanged, therefore the system is unchanged.

But the risk boundary may have moved.

A permission that was harmless for yesterday’s model may become consequential for tomorrow’s model.

A monitoring mechanism that detected yesterday’s failures may not detect tomorrow’s.

Capability changes must therefore be treated as system changes.

Impact on Nekonečný Mír

* Model upgrades require explicit revalidation.
* Agent permissions must be reviewed after material capability changes.
* New tools require new threat and failure analysis.
* Historical agent evals cannot automatically certify a new model version.
* Paper-trading approval does not automatically transfer between materially different agent versions.
* Risk limits remain external to model capability.
* Monitoring must evolve alongside agent sophistication.
* Tool access should be granted according to demonstrated need, not available capability.
* Production promotion remains version-specific.
* Capability increases never silently expand authority.

Projects HQ Principle

When capability changes, trust must be earned again.
